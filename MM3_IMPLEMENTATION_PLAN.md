## How to run a phase
Open Claude Code in `/home/nick/Work/MeetingMaster3` and type one of:
- `/phase`: run the next eligible phase. It checks dependencies, tells you if you're on the wrong model, resumes an `In progress` phase, and asks about any open questions it needs.
- `/phase 03`: run a specific phase. Interim tuning rounds have a letter suffix: `/phase 15a`.
- `/phase status`: show progress and what's next, without doing any work.
- `/phase-add [after NN] <request or file>` (or plain `/phase-add`, which asks you what and where): plan a **new** phase from a change request (ADR-0034). It grounds the request in the code, asks you about owner decisions once, writes the prompt, row and planning log entry, rewires Phase 16, and commits to `main`. It does no product work and does not claim; run the new phase later with `/phase <ID>`. A fill-in intake form is in [`prompts/MM3_change-request-template.md`](prompts/MM3_change-request-template.md).

The command lives in `.claude/commands/phase.md`. Under the hood it reads `CLAUDE.md`, this file and `prompts/MM3_shared-instructions.md`, then executes `prompts/MM3_phase-NN-*.md`. You never need to paste a prompt. Review the agent's close-out summary. Completed phases are merged into `main` automatically (the phase branch is then deleted); nothing is pushed without your confirmation.

Phases run in order. Phases whose dependencies are all complete may run in parallel, for example 05 ∥ 08 and 12 ∥ 13. Each phase is claimed by a `chore(plan): start phase NN` commit on `main` and runs in its own worktree, `../MeetingMaster3-phase-NN`, so parallel sessions never share a checkout. `/phase status` flags any branch or worktree whose row is not `🔄 In progress`.

**Optional hands-off runs (PhaseHypervisor):** `phx preflight /home/nick/Work/MeetingMaster3` asks the foreseeable questions once, then `phx run /home/nick/Work/MeetingMaster3` runs the remaining phases unattended through `/phase NN --auto`, honouring the Gate column. Manual `/phase` stays the standard way; you can switch between the two at any phase boundary, and `/phase` stops if a `phx` supervisor is running this plan.

**Gate column** (read only by PhaseHypervisor; manual `/phase` ignores it): `auto` = may run unattended; `review` = pause for Nick after it; `owner` = Nick starts it. Empty means `auto`.

**Status values:** ⬜ Not started · 🔄 In progress · ⛔ Blocked · ✅ Complete. Always write the icon **and** the word, so the column is easy to scan and still searchable.

### Model rationale
- **Opus 5.5** (`/model claude-opus-5-5`) handles phases with subtle correctness or design risk: the round-trip parser, job state machine, ML pipeline and VRAM handling, voiceprint matching, prompt engineering, the interactive review workspace, and security review.
- **Sonnet 5.5** (`/model claude-sonnet-5-5`) handles well-trodden engineering with clear specs: scaffolding, adapters, CRUD UI, template authoring, Docker and docs. It's faster and cheaper, with ample capability for this work.

15e (template library only) could run in parallel with 15c and 15d, and 15f (generator budgeting and docs) can run in parallel with 15d; 15g (cloud backends, Settings secrets, docs) can run in parallel with 15f, and 15h follows 15g; 15d waits for 15c because both change the review toolbar and the Meetings page. 15i (meeting index and search) and 15j (Ask AI agent) run in sequence after 15h: 15j is built on 15i's search API. 15k (import) follows 15j; 15l (Grok share links) and 15m (Create Project Plan template) both build on 15k and **can run in parallel** (15l touches the importer, the New meeting page and the privacy docs; 15m only the template library, its tests and docs).

**Interim tuning rounds (ADR-0030).** Between hardening (15) and release (16), Nick's feedback from real use is handled in rounds numbered `15a`, `15b`, `15c`…, each a normal phase (row, prompt `prompts/MM3_phase-15x-pre-op-tuning-N.md`, branch `phase-15x-pre-op-tuning`, worktree `../MeetingMaster3-phase-15x`, claim commit, Phase Log entry). A round depends on the previous one, and Phase 16 depends on the last round. **Any phase can be inserted this way** (`09a` after `09`, ADR-0034): use `/phase-add`, which adds the row and prompt and moves the dependencies for you.
